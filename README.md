# YouTube Shorts Auto Scroll

Простая инструкция:

1. Code → Download ZIP, затем распаковать архив.
2. Открыть chrome://extensions и включить «Режим разработчика».
3. Нажать «Загрузить распакованное расширение» и выбрать папку, внутри которой лежит manifest.json.
4. Обновить уже открытые вкладки YouTube. В панели расширения автоскролл должен быть включён.

Ниже более сложная инструкция, описанная техническим языком.

Расширение автоматически подключается на www.youtube.com и перелистывает только Shorts при окончании воспроизведения. Вход с главной страницы, из обычного видео и через историю браузера также поддерживается.

## Применение обновления

1. Откройте chrome://extensions (в Edge: edge://extensions).
2. Нажмите значок круглой стрелки на карточке YouTube Shorts Auto Scroll. Версия должна стать 1.1.1.
3. Один раз обновите уже открытые вкладки YouTube, чтобы убрать старый скрипт и загрузить новый.
4. Проверьте, что расширение включено и доступ к www.youtube.com разрешён постоянно, а не только по нажатию.

Переустанавливать расширение не нужно. После этого при новых открытиях YouTube скрипт запускается автоматически. Установка Node.js и npm для использования расширения не требуется.

На странице Shorts слева внизу появляется «Автоскролл 1.1.1» и состояние: воспроизведение со счётчиком времени, пауза, ожидание загрузки или причина сбоя. Если надписи нет после обновления вкладки, новая версия скрипта не подключилась. Если надпись есть, её текст помогает определить причину без консоли разработчика.

## Что исправлено

- Скрипт подключается на всех страницах YouTube: переход внутри сайта в Shorts больше не оставляет страницу без скрипта.
- Выбирается видимое видео с учётом прокручиваемого контейнера и активного плеера.
- Исправлена проверка нулевой высоты body на YouTube: размеры корневого элемента больше не отсекают видимое видео. Атрибут aria-hidden также не считается признаком визуального скрытия.
- Отслеживаются события видео, замена элементов страницы и переходы YouTube; резервная проверка выполняется каждые 500 мс.
- Зацикливание текущего видео отключается, чтобы можно было обработать его окончание.
- Следующий ролик включается через кнопку Shorts. При неудаче выполняется повтор с паузой и попытка прокрутки к следующему элементу.
- Смена адреса раньше замены видео не вызывает повторного переключения. Пауза пользователя сохраняется.

## Проверки для разработки

```sh
npm ci
npm test
npx playwright install chromium --no-shell
npm run test:browser
```

`npm test` проверяет 20 сценариев в jsdom с моделируемыми временем, геометрией и состоянием видео. Это проверка логики, а не воспроизведения в настоящем браузере.

`npm run test:browser` загружает расширение в отдельный временный профиль Chromium и использует локальную HTML-страницу с настоящими медиа-событиями. Запросы тестовой страницы перехватываются, YouTube не открывается.

Если комплектный Chromium не запускается (в этом окружении Windows сообщает ошибку SideBySide), можно проверить скрипт в установленном Edge:

```powershell
$env:SCROL_TEST_CHANNEL = 'msedge'
npm run test:browser
```

В этом режиме проверяется скрипт, подключённый перед загрузкой страницы, а не установка расширения: Edge не поддерживает такой способ загрузки расширений из командной строки. Все 12 браузерных сценариев и 20 логических тестов прошли. Ошибка определения видимости также воспроизведена на действующем YouTube. После исправления в отдельном тестовом профиле проверены три автоматических перехода подряд при ускоренном воспроизведении (8x), без нажатия кнопки «следующее» тестом. На пользовательском профиле установка и разрешения отдельно не проверялись.

Правила подключения скриптов: [Chrome content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts). Особенности окончания зацикленного видео: [MDN ended](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/ended_event).
